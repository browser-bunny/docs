## Create a project key

1. Select a project in the [dashboard](https://dash.browserbunny.dev). Every account
   starts with a **Default** project.
2. Create or copy an API key for that project.
3. Store it in `BROWSERBUNNY_API_KEY` in your server environment or CI secret store.

The key determines where tests are created and which tests you can read, cancel,
or inspect. See [API client setup](/client-setup/humans) for connection prerequisites.

## Verify access

Send the key as a bearer token on every `/v1` request. List environments to verify
that the key works:

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/environments" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    catalog = client.environments.list()
    print(catalog)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/environments", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const catalog = await response.json();
if (!response.ok) throw new Error(JSON.stringify(catalog));
console.log(catalog);
```

</CodeGroup>

## Choose an API environment

| Environment | Base URL |
| --- | --- |
| Production | `https://api.browserbunny.dev` |
| Staging | `https://api.staging.browserbunny.dev` |

Use a key issued in the same environment as the endpoint.

## Understand access

- **Project access:** use a different project's key to switch projects. The create
  request does not accept `project_id`.
- **API authentication:** dashboard cookies do not authenticate `/v1` requests.
- **Dashboard links:** test and session URLs require sign-in to the owning account.
- **Test minutes:** an API key does not provide minutes. Submission can be rejected
  when minutes are unavailable or reserved pending settlement.

See [errors and limits](/errors-and-limits) for rejected requests.
