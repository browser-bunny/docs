## Create an API key

1. Sign in to the [dashboard](https://dash.browserbunny.dev).
2. Create or copy an API key for your account.
3. Store it in `BROWSERBUNNY_API_KEY` in your server environment or CI secret store.

The key grants access to all tests in its owning account. You can create tests,
read results, cancel tests, and inspect evidence. Continue to [your first test](/client-setup/humans#2-create-your-first-test).

## Verify access

Send the key as a bearer token on every `/v1` request. List devices to verify
that the key works:

<CodeGroup>

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    catalog = client.devices.list()
    print(catalog)
```

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/devices" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/devices", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const catalog = await response.json();
if (!response.ok) throw new Error(JSON.stringify(catalog));
console.log(catalog);
```

</CodeGroup>

## API base URL

Send all API requests to `https://api.browserbunny.dev`.

## Understand access

- **Account access:** every active key can access all tests owned by its account.
  A key cannot access another account’s tests.
- **API authentication:** dashboard cookies do not authenticate `/v1` requests.
- **Dashboard links:** test and session URLs require sign-in to the owning account.
- **Test minutes:** an API key does not provide minutes. Submission can be rejected
  when minutes are unavailable or reserved pending settlement.

See [errors and limits](/errors-and-limits) for rejected requests.
