## Select browsers

An environment names the device category, operating system, browser, and release.
Each selected environment gets one execution of your instructions.

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
  "start_url": "https://example.com",
  "instructions": "Verify that the page heading is Example Domain.",
  "environments": [
    {
      "device": "desktop",
      "os": "windows",
      "browser": "chrome",
      "browser_version": "latest"
    },
    {
      "device": "desktop",
      "os": "windows",
      "browser": "firefox",
      "browser_version": "previous"
    },
    {
      "device": "desktop",
      "os": "windows",
      "browser": "edge",
      "browser_version": "latest"
    }
  ]
}'
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.create(
        start_url='https://example.com',
        instructions='Verify that the page heading is Example Domain.',
        environments=[
            {
                "device": "desktop",
                "os": "windows",
                "browser": "chrome",
                "browser_version": "latest"
            },
            {
                "device": "desktop",
                "os": "windows",
                "browser": "firefox",
                "browser_version": "previous"
            },
            {
                "device": "desktop",
                "os": "windows",
                "browser": "edge",
                "browser_version": "latest"
            }
        ],
    )
    print(test)
```

## Supported environments

Windows desktop supports **six combinations**: Chrome, Firefox, and Edge, each
with `latest` or `previous`. AWS Device Farm TestGrid starts browsers on demand
and releases them after execution.

| Field | Accepted values |
| --- | --- |
| `device` | `desktop` |
| `os` | `windows` |
| `browser` | `chrome`, `firefox`, `edge` |
| `browser_version` | `latest`, `previous` |

### Defaults and validation

- **Default environment:** Windows desktop, Chrome, `latest`.
- **Omitted selection:** omitting `environments` creates one default execution.
- **Omitted fields:** each field uses its corresponding default above.
- **Explicit selection:** supply a nonempty list of distinct combinations after
  defaults are applied.
- **Invalid selection:** the API rejects it without substituting another target.

### Release selection

| Selector | Meaning |
| --- | --- |
| `latest` | The latest release AWS offers for that browser |
| `previous` | The preceding release AWS offers for that browser |

AWS manages the Windows version.

### Requested and observed versions

| Execution field | Meaning |
| --- | --- |
| `environment` | Your requested configuration |
| `actual_environment` | Observed OS and installed browser versions after allocation; null until available |

## Discover capabilities

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/environments" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    catalog = client.environments.list()
    print(catalog)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/environments", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const catalog = await response.json();
if (!response.ok) throw new Error(JSON.stringify(catalog));
console.log(catalog);
```

</CodeGroup>

### Read the catalog

| Response field | Meaning |
| --- | --- |
| `default` | The environment used when you omit selection |
| `data` | Available combinations and their capabilities |

Copy only the four selection fields into a create request. The `capabilities`
object is read-only.

### Check supported features

- **File uploads:** read `capabilities.file_upload` for file-input upload support.
- **Network requests:** `capabilities.network_capture` is `true` when network
  information is available. See [network activity](/network) for request details.
- **Conditions:** read `capabilities.conditions` for support, deployment enablement,
  and any unavailable reason.

Network, locale, and timezone conditions currently require **Chrome** and must be
verified in each session. See [conditions](/conditions) before selecting multiple browsers.
