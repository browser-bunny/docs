Connect once with your project API key. Your agent can discover environments,
create tests, read results and logs, prepare bug reports, and request cancellation through MCP.

## Before you start

1. Create a project API key in the [dashboard](https://dash.browserbunny.dev).
2. Make sure the account has test minutes before creating tests.
3. Choose an MCP client that supports Streamable HTTP and an Authorization header.

The key selects the project. Discovering environments and reading results do not
start a browser or consume test minutes.

## Connect the server

```text MCP server URL
https://api.browserbunny.dev/v1/mcp
```

| Setting | Value |
| --- | --- |
| Name | `browserbunny` |
| Transport | Streamable HTTP |
| Authentication | Project API key in `Authorization: Bearer YOUR_PROJECT_API_KEY` |

### Choose your client

<Tabs>
<Tab title="Codex">

Merge this entry into `~/.codex/config.toml`:

```toml
[mcp_servers.browserbunny]
url = "https://api.browserbunny.dev/v1/mcp"
bearer_token_env_var = "BROWSERBUNNY_API_KEY"
```

Set the key in the environment that launches Codex, then start a new session:

```bash
export BROWSERBUNNY_API_KEY="YOUR_PROJECT_API_KEY"
codex
```

For the desktop app, make the variable available to the app's process and restart
it after changing the environment. See the
[Codex MCP guide](https://developers.openai.com/codex/mcp).

</Tab>
<Tab title="Claude Code">

      "headers": {

Set the key before launching Claude Code:

</Tab>

See the [VS Code MCP guide](https://code.visualstudio.com/docs/agent-customization/mcp-servers).

</Tab>
<Tab title="Other clients">

1. Add a remote MCP server named `browserbunny`.
2. Set its URL to `https://api.browserbunny.dev/v1/mcp`.
3. Select HTTP transport.
4. Add `Authorization: Bearer YOUR_PROJECT_API_KEY` using the client's secret settings.
5. Connect and enable the server's tools.

This server uses project API keys. Choose a client that allows custom headers;
clients that require an OAuth sign-in flow are not supported by this connection.

</Tab>
</Tabs>

Keep your key in a secret setting or environment variable. Do not paste it into
agent prompts or commit it to your repository. The configurations above reference
the key without storing its value in the file.

## Verify the connection

Ask your agent:

```text
Use BrowserBunny's list_environments tool and tell me which browsers
and versions are available. Do not create a test yet.
```

A working connection exposes these tools:

| Tool | What it does |
| --- | --- |
| `list_environments` | Discover supported browsers, versions, and capabilities |
| `create_test` | Submit a test and return its ID |
| `list_tests` | List tests in your project |
| `get_test` | Read status, execution checks, errors, and dashboard links |
| `get_test_report` | Read structured findings and Markdown for a bug handoff |
| `get_test_logs` | Read or poll test events |
| `get_test_network` | Read network requests, optionally showing only errors |
| `cancel_test` | Request cancellation |

## Create your first test

Give your agent this task:

```text
Use BrowserBunny to create a test for https://example.com with these
instructions: "Verify that the page heading is Example Domain."

Use the default environment. Generate an idempotency key for this
submission and keep the same key if you need to retry it.

Retain the returned test ID. Poll get_test about every two seconds
until terminal, then report the status, checks, and dashboard URL.
```

### Test inputs

`create_test` accepts the same test fields as the [API](/api-reference/create-test):

| Input | Requirement |
| --- | --- |
| `start_url` | Required public HTTPS starting page |
| `instructions` | Required actions and checks in ordinary language |
| `environments` | Optional browser selections; defaults to Windows Chrome `latest` |
| `files` | Optional list of public HTTPS file URLs |
| `idempotency_key` | Required for MCP submissions; unique to the intended test |

An idempotency key must be 8–128 characters using letters, numbers, `_`, `.`, `:`,
or `-`. Reuse the key and all inputs after an uncertain response. Reusing it with
changed inputs returns `conflict`. A new intended test needs a new key.

### Follow results

- **Submission:** returns after acceptance; the browser test continues asynchronously.
- **Polling:** pass the returned `test_id` to `get_test` about every two seconds.
- **Terminal statuses:** `passed`, `failed`, `inconclusive`, `error`, and `cancelled`.
- **Logs:** use `get_test_logs`; follow `next_cursor` for more pages or `cursor` for new events.
- **Bug handoff:** use `get_test_report` with `test_id`; optionally select one
  `execution_id`. Use its structured `executions` for analysis or `markdown` for a ticket.
- **Cancellation:** call `cancel_test`, then poll until terminal.
- **Disconnected client:** accepted tests continue. Reconnect and use the saved ID.

The response fields match the [API reference](/api-reference/get-test). Tool failures
set `isError` and return `error.code`, `message`, `param`, and `request_id`.
See [results](/results) for execution checks, evidence, and usage.

## Troubleshoot setup

| Symptom | Next step |
| --- | --- |
| Connection returns `401` or `403` | Check the Authorization header, key status, and MCP server URL above |
| Agent only has documentation search | Connect to the API MCP URL above and enable its test tools |
| `minutes_required` | Add test minutes to the account that owns the key |
| `invalid_request` | Check the named field against the tool's input schema |
| `not_found` | Use a test ID from the project selected by this key |
| `conflict` | Reuse the original inputs for a retry, or a new key for a new test |
| Opening the MCP URL in a browser fails | Connect through an MCP client; the endpoint expects authenticated protocol requests |

## Optional documentation search

For documentation search alongside the test tools, add a second server named
`browserbunny-docs` with no authentication:

```text Documentation MCP server URL
https://browserbunny.dev/docs/mcp
```

The MCP shortcuts beside **Copy Page** connect to this documentation server.
Use the setup above for creating and managing tests.
