## 1. Create an API key

1. Open the [dashboard](https://dash.browserbunny.dev).
2. Create an API key for your account, then set it in your terminal:

```bash
export BROWSERBUNNY_API_KEY="YOUR_API_KEY"
```

Keep the key on your server or in CI. Your account needs test minutes to run a test.

## 2. Create your first test

This test checks the heading on `example.com` in Chrome on Windows, using the
latest browser version available from AWS.

<Tabs>
<Tab title="Python">

Install the client with Python 3.10 or newer:

```bash
python -m pip install --upgrade https://api.browserbunny.dev/downloads/browserbunny-0.12.0-py3-none-any.whl
```

Save as `test.py` and run `python test.py` in the same terminal:

```python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.create(
        start_url="https://example.com",
        instructions="Verify that the page heading is Example Domain.",
        devices=["desktop-chrome"],
    )
    print(test)
```

</Tab>
<Tab title="cURL">

Run in the same terminal with cURL 7.76 or newer:

```bash
curl --fail-with-body "https://api.browserbunny.dev/v1/tests" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
  "start_url": "https://example.com",
  "instructions": "Verify that the page heading is Example Domain.",
  "devices": ["desktop-chrome"]
}'
```

</Tab>
<Tab title="JavaScript">

Use Node.js with built-in `fetch`. Save as `test.mjs` and run `node test.mjs`
in the same terminal:

```javascript
const response = await fetch("https://api.browserbunny.dev/v1/tests", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    start_url: "https://example.com",
    instructions: "Verify that the page heading is Example Domain.",
    devices: ["desktop-chrome"]
  })
});
const test = await response.json();
if (!response.ok) throw new Error(JSON.stringify(test));
console.log(test);
```

</Tab>
</Tabs>

| Input | What to provide |
| --- | --- |
| `start_url` | The public HTTPS page where the test starts |
| `instructions` | What to do and what to verify |
| `devices` | Device names to test; defaults to `["desktop-chrome"]` |

## 3. Review the result

A successful response (`202`) means your test was accepted. Browser work continues
in the background.

- **Save `id`:** use it to [read the test](/api-reference/get-test) later.
- **Open `url`:** sign in to see the result, checks, and session evidence in the dashboard.
- **Found a bug?** [Get a bug report](/api-reference/get-test-report) to share with your coding agent.

For polling and status meanings, see [follow a test](/results).
If submission fails, check [errors and limits](/errors-and-limits).
If the response is lost, check [recent tests](/api-reference/list-tests) before submitting again.
