## Supply upload sources

1. Pass public HTTPS source URLs in `files`.
2. Describe which file to upload and which webpage input to use.
3. State whether to submit the form and what acceptance should look like.

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
  "start_url": "https://example.com/upload",
  "instructions": "Upload the invoice PDF into Attachment, click Upload, and verify acceptance.",
  "files": [
    "https://files.example.com/invoice.pdf"
  ]
}'
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.create(
        start_url='https://example.com/upload',
        instructions='Upload the invoice PDF into Attachment, click Upload, and verify acceptance.',
        files=[
            "https://files.example.com/invoice.pdf"
        ],
    )
    print(test)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    "start_url": "https://example.com/upload",
    "instructions": "Upload the invoice PDF into Attachment, click Upload, and verify acceptance.",
    "files": [
      "https://files.example.com/invoice.pdf"
    ]
  })
});
const test = await response.json();
if (!response.ok) throw new Error(JSON.stringify(test));
console.log(test);
```

Replace the example URLs with your test page and fixture.

### How sources are used

- **Upload permission:** your instructions authorize the upload; supplying a URL
  alone does not.
- **Destination:** the agent selects a source for an observed webpage file input.
- **File contents:** files are not interpreted as documents or treated as
  navigation destinations.

## File requirements

| Requirement | Limit or behavior |
| --- | --- |
| Source URL | Public HTTPS; at most 2,000 characters |
| File size | At most 10 MiB per file |
| Download duration | At most 30 seconds |
| Redirects | At most three |
| Network access | Every connection must resolve to public addresses |
| Authentication | Downloads do not use browser cookies or custom authorization |

Keep source URLs accessible until the upload step. Temporary files are removed
after transfer or failure.

### Rejected URL content

- Embedded credentials or private addresses.
- Raw whitespace or control characters.
- Backslashes, quote delimiters, or angle brackets.

Percent-encoded values remain unchanged.

### Storage and visibility

- **Exact sources:** file URLs retain their strings and list order.
- **Authenticated response:** the test response returns the supplied list.
- **Reports and logs:** derived reports and logs redact source URLs.
- **Duplicates:** duplicate URLs remain in the list without adding upload actions.
- **No sources:** omit `files`, or supply `null` or an empty list.

## Verify the upload

For a submitted upload, the agent checks fresh rendered evidence after selecting
the file and submitting the form.

| Evidence | Result |
| --- | --- |
| Application displays acceptance | Supports the requested acceptance check |
| Application displays rejection | The check fails |
| Evidence is missing or changing | The result is inconclusive |
| Only an input, click, or progress indicator is visible | Does not establish acceptance |

### Verification boundaries

- A file-selection-only request does not require submission.
- Displayed acceptance does not prove server persistence.
