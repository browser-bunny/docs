Pass public HTTPS URLs in `files`, then explain which file to upload and where:

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
  "start_url": "https://example.com/upload",
  "instructions": "Upload the invoice PDF into Attachment, click Upload, and verify acceptance.",
  "files": [
    "https://files.example.com/invoice.pdf"
  ]
}'
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.create(
        start_url='https://example.com/upload',
        instructions='Upload the invoice PDF into Attachment, click Upload, and verify acceptance.',
        files=[
            "https://files.example.com/invoice.pdf"
        ],
    )
    print(test)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    "start_url": "https://example.com/upload",
    "instructions": "Upload the invoice PDF into Attachment, click Upload, and verify acceptance.",
    "files": [
      "https://files.example.com/invoice.pdf"
    ]
  })
});
const test = await response.json();
if (!response.ok) throw new Error(JSON.stringify(test));
console.log(test);
```

</CodeGroup>

Replace the example URLs with your test page and fixture. Supplying files does
not itself authorize an upload. The agent uses your instructions to select a
source for an observed webpage file input. It does not interpret file contents
as documents or treat supplied sources as navigation destinations.

## File requirements

Each URL must be public HTTPS and at most 2,000 characters. Credentials, private
addresses, raw whitespace, control characters, backslashes, quote delimiters,
and angle brackets are rejected. Percent-encoded values remain unchanged.

Downloads are limited to **10 MiB per file**, **30 seconds**, and **three redirects**.
Every connection must resolve to public addresses. Keep URLs accessible until
the upload step; downloads do not use browser cookies or custom authorization.
Temporary files are removed after transfer or failure.

File URLs retain their exact strings and list order. The authenticated test response
returns the supplied list; derived reports and logs redact source URLs. Duplicate
URLs remain in the list without adding upload actions. Omitting `files`, or
supplying null or an empty list, means no separately supplied sources.

## Verify the result

For a requested submitted upload, the agent checks fresh rendered evidence of
application acceptance after selecting the file and submitting. A populated input,
click, or progress indicator alone cannot establish acceptance. A displayed
rejection fails; missing or changing evidence is inconclusive.

An explicit file-selection-only request does not require submission. Application
acceptance is evidence of the displayed result, not proof of server persistence.
You can combine uploads with supported [network conditions](/conditions).
