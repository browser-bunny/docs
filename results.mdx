A **test** contains your instructions and one **execution** per selected environment.
Test IDs begin with `test_`; execution IDs begin with `exec_`.

## Follow status

Read the test about every two seconds until it reaches a terminal status.
Replace `TEST_ID` with the ID returned when you created the test.

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests/TEST_ID" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.get("TEST_ID")
    print(test)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests/TEST_ID", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const test = await response.json();
if (!response.ok) throw new Error(JSON.stringify(test));
console.log(test);
```

</CodeGroup>

| Status | Meaning |
| --- | --- |
| `queued` | Accepted and waiting to start |
| `running` | Execution is in progress |
| `cancelling` | Cancellation is requested; work and cleanup are finishing |
| `passed` | Requested checks passed |
| `failed` | A requested check failed |
| `inconclusive` | Available evidence could not establish the result |
| `error` | Preparation or execution could not complete |
| `cancelled` | The test was cancelled |

The last five statuses are terminal. Test status becomes terminal after every
execution finishes, including browser cleanup. For mixed results, the aggregate
uses the precedence `error`, `failed`, `cancelled`, `inconclusive`, then `passed`.
Inspect executions to see each environment's result.

| Test field | Meaning |
| --- | --- |
| `execution_counts.total` | Number of executions |
| `execution_counts.finished` | Number finished, including failures and cancellations |
| `executions` | Per-environment status, checks, conditions, and evidence links |
| `url` | Dashboard page for the test |
| `start_url`, `instructions`, `files` | Submitted inputs; surrounding instruction whitespace is trimmed when stored |
| `project_id`, `project_name` | Project selected by the API key |
| `started_at`, `finished_at` | Execution timing; null before applicable |
| `usage`, `billing` | Accounting snapshots, when available |

Each execution records the requested `environment`, observed `actual_environment`,
`status`, `phase`, timestamps, and `session_url`. Its `error` is either null or an
object with `code` and `message`. Preparation can fail before any browser exists.
`phase` is `queued`, `planning`, `starting`, `executing`, `checking`, `cleanup`, or
`finished`; it describes the current stage separately from the result status.

`checks` contain names, status, summaries, assertions, and available evidence or
coverage details. `conditions` contains resolved settings and their verification.
Read these fields to distinguish a website failure from unsupported setup or
insufficient evidence. Dashboard and session URLs require account sign-in.

## List tests

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests?limit=50" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    page = client.tests.list(limit=50)
    print(page)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests?limit=50", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const page = await response.json();
if (!response.ok) throw new Error(JSON.stringify(page));
console.log(page);
```

</CodeGroup>

## Read logs

<CodeGroup>

```bash cURL
curl --fail-with-body "https://api.browserbunny.dev/v1/tests/TEST_ID/logs?limit=200" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    page = client.tests.logs("TEST_ID", limit=200)
    print(page)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests/TEST_ID/logs?limit=200", {
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const page = await response.json();
if (!response.ok) throw new Error(JSON.stringify(page));
console.log(page);
```

</CodeGroup>

Pass `next_cursor` unchanged to get the next page. Test pages contain up to 100
items; log pages contain up to 500 events. Use an execution's ID as `execution_id`
to filter logs. Pagination fills the page with matching events before returning a
continuation cursor.

For logs, `next_cursor: null` means you have caught up. Retain the returned `cursor`
watermark and pass it later to read newly appended events. Test-level log events
have `execution_id: null`.

## Cancel and clean up

<CodeGroup>

```bash cURL
curl --fail-with-body -X POST "https://api.browserbunny.dev/v1/tests/TEST_ID/cancel" \
  -H "Authorization: Bearer $BROWSERBUNNY_API_KEY"
```

```python Python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.cancel("TEST_ID")
    print(test)
```

```javascript JavaScript
const response = await fetch("https://api.browserbunny.dev/v1/tests/TEST_ID/cancel", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.BROWSERBUNNY_API_KEY}`
  }
});
const test = await response.json();
if (!response.ok) throw new Error(JSON.stringify(test));
console.log(test);
```

</CodeGroup>

Cancellation is cooperative. Continue polling until a terminal status confirms
that execution and cleanup have finished. Cancelling a terminal test returns it
unchanged. Closing a connection or reaching a local polling timeout does not
cancel the remote test.

## Read usage

Read aggregate `usage` and per-execution `usage` from the test response.
`browser_seconds` reports browser time; `complete` says whether that time has
been confirmed. This confirmation is independent of the test status. Null usage
means no snapshot is available; an incomplete value may still change.

`billing` contains `status`, `amount_cents`, `currency`, `credit_seconds_used`, and
`invoice_url` when available. Billing can settle after the test ends. Follow your
account's available minutes and billing state in the dashboard.
