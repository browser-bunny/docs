Python 3.10 or newer is required. Install the hosted wheel:

```bash
python -m pip install --upgrade https://api.browserbunny.dev/downloads/browserbunny-0.6.0-py3-none-any.whl
export BROWSERBUNNY_API_KEY="YOUR_PROJECT_API_KEY"
```

The package is not published to PyPI. A bare `pip install browserbunny` is not the
installation path for this SDK.

## Run a test and wait

```python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    result = client.run(
        start_url="https://example.com",
        instructions="Using a 3G connection, verify that the page heading is Example Domain.",
        platforms=["windows"],
    )
    print(result["outcome"], result["run_url"])
```

`BrowserBunny(api_key=None, base_url=None, *, environment=None, timeout=30.0, transport=None)` reads
`BROWSERBUNNY_API_KEY` when the key is omitted. Production is the default. Use
`environment="staging"` or `BROWSERBUNNY_ENV=staging` for staging; `base_url` or
`BROWSERBUNNY_BASE_URL` overrides the endpoint. Explicit arguments take priority.
The constructor's `timeout` is the HTTP request timeout in seconds. `transport` accepts an HTTPX transport for custom transport or offline testing.

## Start now, follow later

```python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    run = client.runs.create(
        start_url="https://example.com",
        instructions="Verify that the page heading is Example Domain.",
        platforms=["windows"],
        idempotency_key="ci-homepage-001",
    )
    print(run["id"], run["run_url"])
    result = client.runs.wait(run["id"], timeout=900, poll_interval=2)
    print(result["outcome"])
```

| Method | Arguments and behavior |
| --- | --- |
| `client.devices.list()` | Return the catalog and account availability |
| `client.run(start_url, instructions, platforms, *, files=None, idempotency_key=None, timeout=900, poll_interval=2)` | Resolve platforms, submit, and wait |
| `client.runs.create(start_url, instructions, devices=None, *, platforms=None, files=None, idempotency_key=None)` | Submit and return immediately; omitting selectors uses your account’s enabled configurations |
| `client.runs.get(run_id)` | Return current lifecycle, verdict, results, and usage |
| `client.runs.wait(run_id, timeout=900, poll_interval=2, *, terminal_statuses=None)` | Poll until the parent finishes |
| `client.runs.logs(run_id, test_id=None, cursor=None, limit=200)` | Return a single log page |
| `client.runs.cancel(run_id)` | Request cooperative cancellation |
| `client.close()` | Close HTTP connections; the context manager calls this automatically |

Use either `platforms` or `devices` in `runs.create()`. OS-based platform selection
is an SDK convenience, resolved into the HTTP `devices` field. See
[environment selection](/devices) and [file uploads](/files).

Responses are dictionaries, including additional server fields. Read usage from
`client.runs.get(run_id)`.
The API key sets the project; neither submission method accepts `project_id`.

## Timeouts and exceptions

The `timeout` on `run()` and `wait()` controls your local wait, not the remote test
lifetime. On `RunTimeoutError`, use `.run_id` and `.last_run` to resume later.
Timeouts and closing the client do not cancel a run. `terminal_statuses` overrides
the set of parent states that ends polling; its default is `{"complete"}`.

SDK exceptions inherit from `BrowserBunnyError`: `ConfigurationError`,
`AuthenticationError`, `BillingError`, `RateLimitError`, `TransportError`,
`APIError`, `UnsupportedOperationError`, and `RunTimeoutError`. HTTP errors expose
`status_code` and a sanitized `request_id`. Invalid selector values raise
`ValueError`. Locked or unsupported requested platforms raise
`UnsupportedOperationError` before submission.

No automatic POST retry occurs. See [idempotency and errors](/errors-and-limits).
