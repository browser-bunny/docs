Python 3.10 or newer is required. Install the hosted wheel:

```bash
python -m pip install --upgrade https://api.browserbunny.dev/downloads/browserbunny-0.7.0-py3-none-any.whl
export BROWSERBUNNY_API_KEY="YOUR_PROJECT_API_KEY"
```

## Create and wait

```python
from browserbunny import BrowserBunny

with BrowserBunny() as client:
    test = client.tests.create(
        start_url="https://example.com",
        instructions='Using a 3G connection, verify the heading is "Example Domain".',
    )
    result = client.tests.wait(test["id"])
    print(result["status"], result["url"])
    for execution in result["executions"]:
        print(execution["environment"], execution["status"], execution["checks"])
```

`create()` returns after acceptance. `wait()` polls until the test is terminal.
Omitting `environments` selects Windows desktop Chrome, latest release. The SDK
sends the same [environment objects](/environments) as HTTP. The service resolves
and validates them; the SDK does not rewrite instructions or download files.

## Methods

| Method | Behavior |
| --- | --- |
| `client.environments.list()` | Return available environments and capabilities |
| `client.tests.create(start_url, instructions, *, environments=None, files=None, idempotency_key=None)` | Create and return an accepted test |
| `client.tests.get(test_id)` | Read status, executions, checks, usage, and billing |
| `client.tests.list(*, cursor=None, limit=50)` | Return a project test page with `data` and `next_cursor` |
| `client.tests.wait(test_id, *, timeout=900, poll_interval=2)` | Poll until a terminal status |
| `client.tests.logs(test_id, *, execution_id=None, cursor=None, limit=200)` | Return a log page with `data`, `cursor`, and `next_cursor` |
| `client.tests.cancel(test_id)` | Request cooperative cancellation |
| `client.close()` | Close the client's HTTP connections |

Responses are dictionaries with type hints. The API key selects the project.
Use the context manager to close HTTP connections automatically.

For a CI job, pass your own stable `idempotency_key`. Repeat the same request with
that key after an uncertain submission. The SDK generates a fresh key when omitted
and never retries POST requests automatically.

## Timeouts and errors

The `timeout` on `wait()` limits local polling. It does not change the remote
execution or queue deadlines. On `TestTimeoutError`, retain `.test_id` and
`.last_test` to resume later. Closing the client does not cancel remote work.

```python
from browserbunny import APIError, TestTimeoutError

try:
    result = client.tests.wait(test["id"])
except TestTimeoutError as error:
    print("Still pending:", error.test_id)
except APIError as error:
    print(error.code, error.message, error.param, error.request_id)
```

HTTP exceptions include `AuthenticationError`, `ValidationError`, `BillingError`,
`RateLimitError`, and `UnsupportedOperationError`. They expose `status_code`,
`code`, `message`, `param`, `request_id`, and `retry_after` when available.
`TransportError` means a request could not be completed and its remote result
may be unknown. `ConfigurationError` covers client configuration. All SDK errors
inherit from `BrowserBunnyError`; invalid local argument shapes can raise `ValueError`.

## Configure the connection

```python
client = BrowserBunny(api_key="YOUR_PROJECT_API_KEY", timeout=30)
staging = BrowserBunny(environment="staging")
```

The constructor reads `BROWSERBUNNY_API_KEY`, `BROWSERBUNNY_ENV`, and
`BROWSERBUNNY_BASE_URL` when their arguments are omitted. Production is the default.
An explicit `base_url` overrides the environment's hosted URL; explicit arguments
have priority over environment variables. The constructor's `timeout` is the
HTTP request timeout, in seconds.
