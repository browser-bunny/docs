## Retry a submission

Use `Idempotency-Key` on `POST /v1/tests` when a submission may need to be retried.

### Key requirements

- **Length:** 8–128 characters.
- **Characters:** letters, numbers, periods, underscores, colons, or hyphens.
- **Uncertain response:** retry with the original key and request body.
- **New test:** use a new key.

### Submission responses

| Request | Response |
| --- | --- |
| New submission | HTTP `202` |
| Same key and request | HTTP `200` with the existing test; no new execution |
| Same key with changed input | HTTP `409` |

The replay comparison includes the starting URL, trimmed instructions, resolved
environments, project, and nonempty file list. File order matters.

**Release versions can change.** Separate tests using `latest` or `previous` can
resolve to different installed versions. Compare `actual_environment` when reviewing results.

## Handle request errors

Application-generated errors have this structure:

```json
{
  "error": {
    "code": "not_found",
    "message": "Test not found.",
    "param": null,
    "request_id": "req_example"
  }
}
```

### Error details

| Field | Use |
| --- | --- |
| `code` | Identify the application error |
| `message` | Read the error explanation |
| `param` | Find the relevant parameter, when supplied |
| `request_id` | Retain for support, when supplied |

### HTTP status codes

| Status | Cause and next action |
| --- | --- |
| `401` | Missing or invalid key. Use an active project key. |
| `402` | Minutes or billing readiness required. Review account minutes and the error message. |
| `403` | Permission or origin rejected. Check credentials and request origin. |
| `404` | Test or execution is inaccessible. Check the IDs and project key. |
| `409` | Idempotency conflict or minutes pending settlement. Restore original inputs or wait for settlement. |
| `422` | Invalid input. Correct the indicated field, URL, environment, or query. |
| `429` | AWS account or service throttling. Honor `Retry-After` when returned and back off. |
| `500` | Unexpected service error. Retain `request_id` and the submission key before retrying. |
| `503` | Backing service unavailable. Retry reads; retain the original key for submission retries. |

### Gateway errors

AWS API Gateway can reject authentication or throttle a request before the
application receives it.

- **Response shape:** it may return `{"message": "Unauthorized"}`.
- **Request identifier:** application `request_id` fields or `req_` identifiers may
  be unavailable.
- **Handling:** use the HTTP status when application error fields are missing.

## Handle execution errors

A successful submission can later finish with an execution error. Inspect:

- `executions[].error` for its code and message.
- `conditions` on the execution for setup and verification details.
- `checks` on the execution for requested verification results.

See [results](/results) to distinguish request errors, execution errors, and website failures.

## Input limits

| Input | Limit |
| --- | --- |
| `start_url` | 8–2,000 characters; public HTTPS without credentials or private addresses |
| `instructions` | 5–3,000 characters; minimum also applies after trimming |
| `environments` | Nonempty when supplied; distinct supported combinations after defaults |
| File source URL | At most 2,000 characters per URL |

## Execution and transfer limits

| Setting | Limit |
| --- | --- |
| Browser planning | At most eight concise browser steps per test |
| Queue deadline | Up to six hours to start an execution |
| Browser work | Nine minutes including startup, followed by cleanup and failure handling |
| File transfer | 10 MiB, 30 seconds, up to three redirects per file |

### Plan workflows that fit

- Character limits do not guarantee that every workflow fits the planner.
- Browser steps and generated checks share a bounded plan.
- Viewport sweeps can use several steps.
- Split longer workflows into separate tests.

## Pagination limits

| Resource | Page size |
| --- | --- |
| Tests | 1–100; default 50 |
| Logs | 1–500; default 200 |
| Cursor | At most 2,048 characters; pass the returned value unchanged |

## Queuing and billing readiness

- **Browser capacity:** accepted executions can queue while capacity is occupied.
- **Account readiness:** available minutes, credit reservations, and settlement can
  affect admission.
- **Start time:** acceptance does not reserve an immediate browser start.
- **Local timeouts:** polling can time out while the remote test remains queued.
  Retain its ID to resume polling.
